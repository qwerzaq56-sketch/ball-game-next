# 간단한 원화 배치 워크플로우

## 효과 원화 재현에서 확인한 절차 · 10/06

승인된 효과 원화가 있으면 정확 효과 크롭을 직접 입력한다. 없으면 그 원화의 정확 프롬프트와 크롭을 참조해 의미에 맞는 원화를 먼저 만들고, 새 원화의 효과 부분을 다시 크롭해 투명 리소스로 분리한다. 배우/바닥 제거, source 피벗·여백 좌표 보정, 실제 기하 clip과 저강도 합성 후 Game.render에서 비교한다. 소용돌이처럼 형태가 다른 경우는 단순 alpha 감소보다 원화 크롭 재제작으로 해결했다.

raw RGB에 보이는 빛이 alpha0일 수 있으므로 RGBA/실제 Canvas 합성을 확인하기 전 안개 실패로 단정하지 않는다. 생성 원본을 수정하지 않고 캐시 크롭·표시 보정을 기록한다. 효과 범위·방향·수혜 정보는 기존 판정과 일치시키며 모든 실패/비선택 버전도 보존한다. 근거와 잔여 한계: `reports/EFFECT_DIRECTION_V2_20261006.md`.

`python tools/art-batch.py prepare`는 현재 기획 13종을 카탈로그에서 읽고, 원화 영역·게임플레이 참조·항목별 프롬프트·manifest를 준비한다. 기존 생성 파일은 덮어쓰지 않는다. Python/Pillow와 Node가 필요하며 게임 런타임 의존성이 아니다.

Codex는 manifest의 준비된 항목마다 기본 imagegen을 한 번 호출한다. 별도 API키 없이 이번 배치 전체를 실행했다. 이 Python 도구 자체는 생성 API를 호출하지 않으며 무인 CLI 생성기라고 주장하지 않는다.

`python tools/art-batch.py record --id ID --file 생성원본.png`는 원본 복사·알파/크기·SHA256·시간 기록을 수행한다. 이미 결과가 있으면 중단해 원본을 보호한다. 재시도는 별도 batch 버전/결과명으로 보존한다. `status`로 manifest 확인.

`tools/art-batch-review.html`에서 전체 비교 및 원화/프롬프트 링크를 본다. 다음 단계는 오브젝트 원화와 gameplay-regions-a/b를 함께 넣어 새 게임플레이 원화를 생성한 뒤 전체 룩을 기준으로 선택·실제 적용한다. 생성 완료를 스타일 승인 또는 실제 게임 반영 완료로 취급하지 않는다.

전체 폴더 `assets/art-batches/scene-coherent-v1/`가 공유 단위다. 다른 PC에서는 prepare로 현재 checkout 경로에 맞게 참조 경로를 갱신한다. 자동 판정은 범위/파일/알파 검사까지만이며 자연스러운 최종 룩은 실제 장면 비교가 필요하다.

ZIP: `python tools/art-batch.py pack --file 출력-v1.zip`. 원화·전체 결과·도구·카탈로그·참조 게임플레이 원본이 함께 들어가며 기존 ZIP 덮어쓰기를 거부한다.


## 실제 배치 후 룩 보정 — 사용자 직접 제안

리소스 생성·연결 다음에 **원화와 실제 게임 장면의 합성 룩 보정**을 필수 단계로 진행한다. 개별 오브젝트만 비슷한 것으로 완료 처리하지 않는다.

1. 같은 지역·카메라 위치·줌·캐릭터 크기로 원화와 실제 화면을 비교한다. 기준 시점은 원화의 비스듬한 탑뷰이며, 옆면을 없애는 것이 아니라 배경과 오브젝트의 관찰각·접지감·광원을 맞춘다.
2. **색보정:** 지역 팔레트에 맞춰 오브젝트의 색온도·명도·채도·그림자 대비를 조정한다. 캐릭터 종족색·공격 전조·위험 구분의 가시성을 유지한다. 원본을 보존하고 적용값 또는 보정본 버전을 기록한다.
3. **크기·비율:** 작은 캐릭터와 성장 캐릭터에 대한 상대 크기, 본체의 가로세로 비율, 줄기·수관·바위 높이, 이미지 여백과 접지 위치를 조정한다. 단순 확대보다 원화 장면 안에서의 비중을 기준으로 판단한다. 과도한 이미지 왜곡은 재제작으로 해결한다.
4. **이펙트·범위 표시:** 이펙트 색·강도·두께·투명도·지속 표현·그림 레이어와 범위 선의 색·두께·투명도·표시 조건을 함께 보정한다. 사용자 직접 정정: 보정된 오브젝트 크기를 기준으로 효과 반경과 실제 판정 범위도 직관적으로 이해되는 수준으로 변경할 수 있다. 본체가 접촉형인지 주변 영역형인지 기능에 맞춰 관계를 정하고, 표시 범위와 실제 판정 범위를 일치시킨다. 효과 대상·쿨다운·게임 난수는 별도 지시 없으면 유지한다. 필요한 위험/방향 정보는 보존한다.
5. 준비·수혜 후·활성/휴식, 줌0.5/1, 작은/성장 캐릭터, 여러 효과가 겹친 장면에서 재확인한다. 자연스러운 배치와 이동 공간도 함께 평가하고, 동일 조건의 전후 캡처·변경값·남은 차이를 과정 로그에 남긴다.

반복 순서: 원화 참조 → 리소스 제작 → 실제 배치 → 색/크기/비율/이펙트/범위 보정 → 합성 화면 비교 → 필요 시 리소스 재제작. 우선순위는 최종 화면의 자연스러움과 게임 정보의 가독성이다. 사용자 요청을 작업 절차에 반영한 것이며, 모든 항목의 보정 완료를 뜻하지 않는다.


### 크기와 효과 범위의 후속 조정 — 사용자 직접 제안·승인

초기 합성 보정에서는 본체의 시각적 크기와 효과 영역의 관계가 자연스럽게 읽히도록 효과 반경·접촉 판정을 함께 맞춘다. 본체와 범위를 반드시 같은 배율로 확대하는 규칙은 두지 않는다. 이후 튜닝은 (1) 본체 크기를 유지하고 범위·판정만 조정하거나, (2) 본체 크기와 범위·판정을 함께 조정하는 두 방식으로 진행한다. 범위 표시를 실제 판정과 함께 갱신하고, 작은/성장 캐릭터·두 줌·범위 안팎에서 직관성과 밸런스를 검증한다. 변경 전후 크기·반경·판정 규칙과 이유를 과정 로그 및 해당 규칙 카드에 기록한다. 이번 수정은 조정 권한과 절차의 승인이고, 개별 오브젝트의 새 수치는 구현·검증 단계에서 결정한다. 이전의 반경·판정 고정 조건보다 이 사용자 정정을 우선한다.


## 지형 제작 기준 정정 — 타일 분리와 레벨 구성 · 2026-10-06

**출처: 사용자 직접 제안·정정.** 풀이 많은 부분 / 풀밭 / 길을 별도 리소스로 제작하고 섞어서 레벨을 구성한다. 숲 텍스처만 확대해 규모감을 만드는 방식은 폐기한다. 아래 기준은 이전의 단일 지면 타일 제작·확대 방침보다 우선한다. 현재 숲 1600 월드 반복 크기는 후속 구현에서 공통 축척으로 교체할 대상이며, 이 문서 수정으로 코드가 변경된 것은 아니다.

### 공통 축척

- 6지역은 같은 월드 단위와 비교 기준을 사용한다. 기존 논리 셀 200, 제작 기준 모듈 400×400(2×2셀)을 유지한다. 출력 이미지 픽셀 수와 게임에서 차지하는 월드 크기는 별도 값이다. 고해상도 이미지를 만든다고 풀·돌까지 확대하지 않는다.
- 풀 한 포기·풀 군락·돌·나무의 기준 크기를 비교판에서 먼저 정한다. 시작 크기는 랜덤이므로 시작 캐릭터에 비례시키지 않고, 고정 size 40 / 100 캐릭터와 같은 줌에서 상대 크기를 확인한다(size는 반지름이 아니라 기존 게임의 크기 값).
- 큰 군락은 같은 크기의 요소를 넓게 조합해 만든다. 반복을 줄이기 위해 한 지역의 전체 텍스처를 늘리거나 다른 지역을 따라 확대하지 않는다. 큰 메타타일도 개별 요소의 축척은 유지한다.

### 섞어서 레벨 구성

단계는 **지역 구분 → 연결된 길·공터와 군락의 밀도 배치 → 타일 선택·전이 → 독립 장식 → 기능 오브젝트 → 효과** 순서다. 셀마다 독립적으로 랜덤 타일을 뽑아 얼룩을 만드는 대신, 몇 셀에 걸친 군락·빈 공간·완만한 길을 구성한다. 길 주변은 성기게, 군락 안쪽은 조밀하게 배치하고 규칙적인 격자·동일 간격 배열을 피한다. 연결 방향은 마스크와 조합으로 만들며, 광원이 구워진 그림을 무작정 회전하지 않는다.

길은 우선 시각적 공간 구분이다. 이동 보너스·충돌·새 게임 규칙은 추가하지 않는다. 장식 배치는 게임 난수와 분리된 좌표 기반 규칙을 사용한다. 기능 오브젝트의 효과 범위·판정 보정은 기존 승인 절차와 별도로 기록한다.

다른 지역도 같은 구조를 적용하되 표현은 다르게 한다: 초원은 흙/풀밭/꽃·풀 군락, 설원은 다져진 눈/눈밭/서리 군락, 사막은 평탄 모래/모래결/드문 식생, 화산은 암반/재/돌 군락, 호수는 잔잔한 수면/물결/수초·물가 패치. 호수의 시각적 통로를 육지로 해석하거나 용암 같은 실제 위험을 장식 타일로 대체하지 않는다.

### 제작·검증 순서

1. 원화의 색·광원·관찰각을 공유하는 숲 구성 요소를 만들고 공통 축척 비교판을 작성한다. ground-005 등 기존 시안·프롬프트는 보존하고 재분리·재제작 참고로 사용한다.
2. 같은 구성 요소로 성긴 공터 / 풀밭 / 조밀한 군락 / 굽은 길 장면을 조합한다. 규모감은 군락 면적과 공간 배치로 평가한다.
3. 실제 게임에서 작은·성장 캐릭터, 줌 0.5 / 1, 다른 지역과의 경계로 비교한다. 풀·돌의 크기 일관성, 길 연결, 타일 이음새, 광원, 몸 색·전조 가독성을 확인한다.
4. 숲 결과가 자연스러우면 나머지 5지역으로 확장한다. manifest에 픽셀 크기 / 월드 크기 / 피벗 / 층 / 밀도 유형 / 연결 규칙 / 원화·프롬프트 버전을 기록한다.

**후속 구현:** 숲 단독 1600 반복 확대를 공통 축척의 구성 요소·배치로 교체한다. 기존 다른 지역을 함께 확대하는 보정은 하지 않는다. 현재 런타임의 800/1600 반복 크기와 제작 기준 400 모듈을 연결하는 조합·캐시 방식은 구현 작업에서 검증한다. 리소스 제작 완료와 실제 적용 완료는 따로 기록한다.


### 작은 비상호작용 데칼 — 사용자 직접 제안 · 2026-10-06

기능이 있는 지형 오브젝트와 별도로 작은 데칼을 제작해 레벨 구성에 사용한다. 데칼은 보상·버프·피해·충돌·AI 목표가 없는 시각 장식이며, 기능 오브젝트처럼 이름·효과 범위·수혜 이펙트를 표시하지 않는다.

- **제작 목록:** 숲의 낙엽·잔가지·이끼·작은 풀·자갈, 초원의 짧은 풀·꽃잎·흙 얼룩, 설원의 눈 자국·얼음 조각, 사막의 작은 돌·마른 풀, 화산의 재·암석 파편, 호수의 수초·물가 잔해. 지역별 대표 몇 종부터 만들고 필요에 따라 확장한다.
