# 숲 원화 조합·기능 식생 구분 1차

사용자 직접 요청: 원화 크롭 참조 유지, 기존 방법론을 조합해 플레이 원화에 가까운 최종 화면을 만들고 성과가 확인되면 워크플로우에 반영. 타일 속 덤불과 기능 오브젝트의 혼동을 해결.

## 적용한 조합

지형 레이어를 마스크로 혼합하는 방식과 별도 장식 배치를 Canvas 2D에 적용했다. 기존 방법론 참고: [Unity Terrain Layers](https://docs.unity.com/en-us/engine/6000.7/manual/creating-environments/script-terrain/terrain-textures/class-terrain-layer), [Godot Decals](https://docs.godotengine.org/en/4.5/tutorials/3d/using_decals.html). 해당 엔진을 도입한 것은 아니며, 현재 게임의 2D 렌더러에 맞춘 조합이다.

1. 승인된 플레이 원화를 수관/가장자리/열매 덤불/장면으로 정확히 크롭해 생성 입력으로 사용. 좌표·원본 SHA256·정확 프롬프트 보존.
2. 빈 이끼 바닥 → 낮은 식생 전이 → 수관 3변형 → 부분 수관 가장자리 → 기능 객체 → 캐릭터/필수 효과 순서로 합성. 공통 800 월드 축척 유지.
3. 수관 변형은 월드 좌표의 연속 가중치로 혼합. 광원 회전/반전 없음. 기존 독립 나무는 수관 실패 시 폴백으로만 사용해 서로 다른 스타일이 겹치는 문제 제거.
4. 타일은 열매 없는 수관·낮은 식생으로, 기능 덤불은 산호색 열매와 독립 실루엣으로 구분. 새 berry-002는 실제 기능 객체에만 사용한다.
5. 기능 덤불/고목 아래에 같은 월드 위상의 바닥을 부드러운 타원으로 드러낸다. 주변 식생 대비를 줄이는 시각 공간이며, 효과 범위는 기존 실제 반경으로 별도 표시. 바닥 패치 전체를 먼저 그려 다른 객체나 범위 표시를 덮지 않도록 한다.

## 생성·적용 상태

채택: canopy-007/008/009, understory-003, edge-003, berry-002. 최초 full-scene 입력 시안과 잘못 생성된 체크 배경 시안004/005/006/understory002는 비교용으로 보존하고 런타임에서 제외했다. canopy 개별 로딩 실패는 기존001로 폴백하며 나머지 지역 로딩을 막지 않는다.

## 검증과 관찰

392/392 테스트 통과. 실제 Game.render에서 줌0.5/1, 5색 이동, 기능 식생 주변 바닥 ON/OFF 비교. 초기 합성에서 서로 다른 그림체의 독립 나무가 중첩되던 문제는 제거됐고, 기능 덤불의 열매와 경계가 배경에서 더 읽히는 것으로 관찰했다. 브라우저 오류/경고0. 6지역 로딩 및 15쌍 경계 fixture 확인. 근거 캡처: forest-composition-001-zoom1.png, ground-off.png, motion.png, pairs.png.

이는 통제된 화면의 시각 관찰이며, 원화와의 픽셀 일치·모든 자연 플레이 배치·전체 효과 중첩 검증을 뜻하지 않는다. 숲의 주기적 반복과 전이부 중복 모양은 남아 있다. 작은 크기에서 세부 문양/얇은 전조의 가독성은 캐릭터·이펙트 묶음에서 추가 확인한다.

## 병목

생성 모델이 타일 요청을 고립된 스프라이트+불투명 체크 배경으로 해석했다. full-bleed, 모든 모서리까지 채움, 패딩/체크/열매 금지를 명시해 재생성으로 해결. 생성 성공과 채택 승인은 분리한다.

숲 최초 줌0.5 렌더에서 약198ms, 이후 같은 장면 줌1 캐시 재사용에서 약2~3ms 관찰. 서로 다른 조건이므로 속도비나 실제 FPS로 해석하지 않는다. 새 청크의 첫 합성이 비용이 드는 구조다. 3변형 가중치를 한 번만 계산하도록 중복 연산을 줄였으며 청크 캐시24, 바닥 패치 캐시40으로 상한을 둔다. 캐시24는 RGBA 청크 픽셀만 약61MB이므로 메모리와 새 청크 진입 시 지연은 후속 측정 대상.

게임의 효과 대상·반경·쿨다운·보상·AI·게임 난수는 변경하지 않았다. 기능 덤불은 자동 재생성형이므로 대기 중에도 몸체를 유지하고 전체를 희미하게 지우지 않는다.
