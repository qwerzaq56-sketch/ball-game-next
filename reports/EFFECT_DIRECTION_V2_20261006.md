# 수혜 원화 기준 효과 재제작 · 2026-10-06

사용자 첨부 `exec-841290c5...png`는 `ally-buffs-001.png`와 SHA256이 같다. 해당 원본의 정확한 프롬프트·효과 크롭을 직접 사용했다. 부족한 전투/능력은 같은 스타일의 원화를 먼저 생성하고, 다시 해당 효과 부분을 정확히 크롭하여 리소스 제작에 입력했다. 원본·좌표·SHA·정확 프롬프트·비선택 시안을 보존했다.

## 적용

- 수혜 4: 잎 보호·강화·서리해제·회복. 원본 actor 피벗을 캐시 크롭 좌표로 변환하고 실제 수혜자에만 합성한다.
- 공통 4: 차징·접촉 피격·회피·실제 성장 pulse. 차징/피격은 필수 벡터를 보존하고, 회피의 방향성 곡선만 회전한다.
- 종족 능력 8 질감: 실제 기본 E/R 10종에 연결. 공격 원뿔·파도 전면·위험 장판은 기존 판정 기하 안에 clip한다. 초대/소환/집결은 시전자와 실제 수혜자의 작은 장식이며 새 공격 장판을 만들지 않는다.
- 흡수 1: 실제 대상→흡수자 관계와 토러스 최단 경로만 사용. 왼쪽을 향한 원본을 표시에서 반전해 방향을 맞춘다. 진행호는 작은 대상의 기존 코드가 담당한다.

실제 게임 수치·판정·효과 대상·쿨다운·게임 난수 변경 없음. 서리/잎 보호막의 질감 출처를 표시용 태그로만 구분한다. 이미지 실패 또는 OFF에서는 기존 벡터가 남는다. 필수 범위선과 기존 UI는 이번 스타일 변경에서 유지했다.

## 검수와 한계

공통 효과 6지역×줌0.5/1의 실제 Game.render 통제 장면과 5색 중첩 로딩 확인. 기본 E/R 10종 시전 성공 및 범위 밖 샘플의 HP/보호막/냉기/명령 불변을 DOM 결과로 확인했다. 초기 검사 루프가 로딩 중의 이전 결과를 읽어 폐기하고, 로딩 완료 조건을 기다려 재검증한 기록만 `abilities-v2-runtime-checks.json`에 저장했다. 자연 플레이의 밸런스·FPS·전체 조합 합격을 뜻하지 않는다.

소용돌이002는 실제 합성에서 두꺼운 초승달이 눈에 띄어 비선택. 동일 효과 원화 크롭으로003을 재생성해 얇은 열린 두 곡선으로 교체하고 실제 화면에서 확인했다. 보호막·회복 등은 실제 성공/비수혜 비교를 유지한다. 흡수의 희소 흰 파편은 원본에 남지만 좁고 낮은 alpha의 실제 연결 밴드에서는 절제된 선으로 사용한다.

브라우저 clip 캡처 일부가 폭을 잘못 렌더한 병목이 있어 화산은 `effects-v2-volcano-1-corrected.png` fullPage로 다시 확인했다. 로딩 결과만으로 캡처 전체의 시각 합격을 주장하지 않는다. 이동/크기/방향/OFF 추가 확인과 최종 테스트 수는 아래 완료 기록에 남긴다.

## 워크플로우에 반영할 성과

1. 승인된 효과 원화를 최우선으로 삼고, 없는 효과는 그 원화의 프롬프트를 바탕으로 의미에 맞는 원화를 먼저 만든다.
2. 정확 효과 크롭 → 배우·바닥 없는 투명 자산 → 피벗/여백 보정 → 실제 Game.render 합성 순서를 따른다.
3. raw RGB 미리보기만으로 안개를 판정하지 않는다. alpha0에 숨은 RGB는 Canvas에서 비가시다. 실제 RGBA와 게임 합성을 확인한 뒤에만 재생성한다.
4. 기하 clip과 저강도 합성으로 실제 정보와 장식을 분리한다. 두꺼운 소용돌이처럼 형태 자체가 다르면 단순 alpha 감소 대신 정확 원화 크롭으로 재제작한다.

생성 근거는 `planning/art-concepts/effect-direction-v2/concept-manifest.json`, 세부 자산/병목은 각 pack manifest와 `PARALLEL_BENEFITS_V2`, `PARALLEL_COMBAT_V2`, `PARALLEL_ABILITIES`, `PARALLEL_ABSORPTION_V2` 보고서에 있다.
