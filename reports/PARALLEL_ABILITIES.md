## 합성 API

`loadAbilityRaster(ids)`는 선택적 비동기 로드, `abilityRasterStatus()`는 loaded/failed/pending을 제공한다. 이미지별 실패가 나머지 로드를 막지 않는다. 원본 여백 크롭 및 일부 알파 보정은 최대 변 256px 캐시에 한 번 적용하며 원본 PNG는 수정하지 않는다.

`drawAbilityRaster(ctx, id, {x, y, width, height, radius, alpha, direction, clip})`는 게임 상태를 읽지 않는다. 부모가 실제 발동 시점·대상·방향·크기·남은 시간을 전달한다. `clip(ctx)`는 기존 판정에 대응하는 벡터 기하를 재사용하며 텍스처 변형 전에 적용된다. 파도는 실제 전면 20 world 폭과 기존 길이·진행 방향에 맞춘다. 기존 전조, 경계, 범위선, 차징량 등 판단 정보는 벡터가 유지한다.

cyan-sweep / blue-wave만 방향 회전한다. 이는 외부 환경광이나 구워진 방향성 그림자가 없는 자발광 패턴이며, 완전한 무광원 이미지라고 주장하지 않는다. 나머지 방사형 장식은 회전하지 않는다. 텍스처가 새 피해 범위·대상·강제 행동을 만들지 않는다.

## 002 재생성 완료 — 현재 등록 버전

부모가 제공한 `planning/art-concepts/effect-direction-v2/abilities-002.png`에서 8개 효과를 정확히 크롭하고, 각각 해당 크롭을 built-in image_gen의 직접 입력으로 사용했다. `references/v2/crop-manifest.json`에 원화 SHA256, 크롭 좌표·크기·SHA256을 보존했다. 여덟 원본 생성 경로는 `generated-sources-002.json`, 프롬프트는 개별 `*-002-prompt.txt`, 픽셀 검사 결과는 `alpha-metrics-002.json`이다. 원본 001은 비선택으로 모두 보존하고 registry와 manifest는 002 8종을 등록했다. 이는 부모의 실제 합성 검수가 끝났다는 의미는 아니다.

cyan-sweep는 넓은 안개 없이 짧은 곡선과 세 조각으로, blue-wave는 세로 이동 전면으로 재배치됐다. green-call의 round mote, yellow-dust의 먹이 같은 다이아 입자를 제거했다. red-muster는 불꽃과 집결을 구분하는 coral partial arcs다. 배우·바닥·그림자·외곽 범위선은 제거됐고 8개 모두 RGBA 알파 최솟값 0을 확인했다.

남은 한계: cyan-shield와 blue-wave에는 광량 금지 지시에도 구워진 블룸이 남았다. 캐시에서 alpha 2.5승, red-embers의 얇은 외곽에서 1.8승을 적용하며 원본은 수정하지 않는다. 나머지는 별도 알파 곡선이 없다. blue-vortex는 실제 원화보다 가운데 crescent가 두꺼워 낮은 합성 alpha 및 원래 영역 clip으로 검수해야 한다. 과장된 독립 스킬 아이콘처럼 보이면 재생성 또는 비선택이 필요하다.

출력 원본 여백 크롭 XYWH와 원본 기준 pivot을 manifest에 명시했고, 캔버스 캐시에 대한 pivot 좌표변환은 유지했다. 테스트는 새 버전 registry로 다시 수행한다. 공유 abilities / abilityPresentation 파일은 수정하지 않았다.

## 알파 없는 RGB와 실제 광량 구분 — 위 블룸 표현 정정

`view_image`에서 넓은 빛처럼 보였다는 사실만으로 실제 게임 합성에서도 넓은 블룸이 존재한다고 판단할 수 없다. 002를 픽셀 단위로 다시 검사한 결과 cyan-shield는 **alpha=0이면서 RGB가 남은 픽셀 1,073,186개**, blue-wave는 **935,041개**다. Canvas의 일반 source-over에서는 이 픽셀이 완전히 보이지 않는다. 위에서 원본의 넓은 구워진 블룸이라고 표현한 것은 숨은 RGB 미리보기와 실제 보이는 광량을 혼동한 판단이므로 이 부분을 정정한다.

실제 양의 알파는 shield 59,105픽셀(전체 3.76%), wave 147,804픽셀(9.40%)이다. 이 중 alpha 1–15는 각각 18,958 / 14,220픽셀이며 미약한 가장자리 또는 광량일 수 있지만 넓은 실제 안개라고 단정할 근거는 없다. 코드의 기존 알파 보정은 현재 보존하고, 합성 적합성은 부모 브라우저 검수로 판단한다. 이 검수에서는 자산·모듈·선택을 다시 수정하지 않았다.

나머지 alpha=0의 nonzeroRGB 픽셀은 vortex 570, sweep 698, green 129, embers 128, muster 437, yellow 347이다. red-embers에는 실제 alpha 1–15 픽셀이 118,834개 있어 약한 외곽 광량의 기여 가능성은 상대적으로 크다. 상세 alpha band별 개수와 실제 alpha>0 픽셀의 RGB 범위를 `visible-alpha-qc-002.json`에 보존했다. RGB 범위 단독값은 위치나 알파 강도를 반영하지 않으므로 밝은 화면을 단정하는 지표로 사용하지 않는다.
