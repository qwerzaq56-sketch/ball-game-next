## 기획에 미치는 영향

- 시작 크기 배수 대신 `size`의 절대값으로 직위 기준을 지정해야 한다. 지름과 반지름 용어를 혼용하지 않는다.
- 성장 누적값 순위는 랜덤 시작 크기를 반영하지 못한다. 원안의 점수 순위를 적용하려면 모든 개체의 점수를 추가해야 한다.
- 최상위 영역 이동은 기존 무작위 배회와 다른 지속 목적지가 필요하다.
- 플레이어는 같은 틱에 부활할 수 있으므로 `alive` 관찰만으로 사망 후 영역 해제를 처리할 수 없다. 패배 이벤트에서 명시적으로 해제해야 한다.
- 컨펌된 제안 001의 크기 비율 비교는 size의 비율로 계산해도 반지름 비율과 같다. 다만 ‘성장 크기’는 누적 growth가 아니라 실제 `size`를 의미해야 한다.
- 제안 001은 일반 감지 범위를 재사용한다. 구현 시 프레이 위협·프레데터 적 추적은 명시적으로 320으로 제한하고 기존 흡수 탐색은 400을 유지하는 것이 문구에 부합한다. 기존 통합 스캔의 의도는 Claude 조사 보고에서 확인한다.
- 하늘색 능력을 설계할 때 보라색 교체인지 6번째 종족 추가인지 사용자 결정을 받아야 한다.
- 최상위 조건 size 100은 현재 두 번째 공격 스택 해금과 연결된다. 플레이어가 기본 설정에서 도달하는 데 필요한 growth는 2500이다. 생성 시 큰 AI도 size 100을 넘을 수 있어 AI 점수와 함께 자격을 판정해야 한다.
- 영역 반경 600의 5개 원 면적 합은 약 565만, 전체 맵 2500만의 22.6%다. 겹침과 경계 절단은 실제 면적을 줄인다. 실제 위험 분포는 별도 실험이 필요하다.

## 후속 구현 확인 지점

설정은 `config/gameBalance.json`, 공통 상태는 `js/entity.js`, 점수 가산은 `js/game.js`와 `js/absorption.js`, 목적지 행동은 `js/ai.js`, 영역 렌더는 `js/game.js`, 역할·직위 HUD는 `js/ui.js`가 주요 연결 지점이다.

저장소의 `GAME_DESIGN.md`와 `BALANCE_NOTES.md`는 Claude가 구현 사실을 관리한다. 별도 ball-game-planning의 기획서는 의도를 관리하며 source의 docs로 복사하지 않는다. 차이는 handoff 보고서에 기록한다.
