# Claude 작업 전달문

작업 영역은 `F:/GPT/ball-game/`이다. [handoff 운영 기준](../../handoff/README.md)을 먼저 읽고, `handoff/tasks/`의 담당 Claude·상태 ready인 TASK부터 진행해줘.

- 구현 기준본: `F:/GPT/ball-game/ball-game-source`.
- 기획 기준본: `F:/GPT/ball-game/ball-game-planning/00_기준/01_게임_기획서.md`, 현재 v0.24.

v0.24의 6절·7절이 현재 능력·명령·AI 분류·종족 기준이다. 역할·공통 성격·프레데터 관계를 분리하고 역할이 바뀌어도 성격을 유지한다. 관계 배회형은 독립형으로 변경했고 포레이저 고정 3유형은 상황별 행동으로 통합했다. 과거 제안 001·004·005의 분류와 충돌하면 현재 기준본을 따른다. 별도 방랑자·보수형·균형형·공격형 성격은 추가하지 않는다.
- 첫 TASK: `F:/GPT/ball-game/handoff/tasks/TASK-001.md`.
- 첫 보고서: `F:/GPT/ball-game/handoff/reports/TASK-001-result.md`.

기획 v0.4의 5절·7절과 제안 004 프레데터 유형은 사용자 컨펌 완료다. 최상위 제안 002-r2가 승인본이며 직접 영역 집결은 대체된 안이다. 지역 제안 003-r2는 컨펌 완료이며 v0.10 8절을 따른다. 사분면 대신 분산 바이옴을 사용하고 큰 바이옴 예외는 아직 미승인이다. 능력은 승인된 6절을 따른다.

첫 작업은 코드 확인·기준선·측정 준비다. 신규 생태계 전체를 한 번에 구현하지 말고 TASK의 범위와 완료 조건을 따라줘. 기획 문서를 source의 docs로 이동하거나 복사하지 않는다. 코드와 기획의 차이는 보고서에 올려줘. 기획의 사실 오류만 `[Claude 정정]` 표시와 함께 정정할 수 있고, 의도와 컨펌 규칙은 임의로 바꾸지 않는다.

source의 브랜치·커밋·PR·push는 Claude가 담당한다. 세션 시작 시 git status, git log -3, 상대 로그를 확인하고 상대 미커밋 변경은 건드리지 않는다. master push/병합(배포), force push, 삭제, 대규모 이동, 게임 방향 변경은 handoff 기준에 따라 사용자 승인이 필요하다.

보고서는 변경 파일, 검증과 재현 방법, 기획서와의 ‘차이’, 측정 결과와 미수행 항목, 구현 커밋, 남은 문제를 포함해줘. 자기 자신의 미래 커밋 해시는 예측하지 않는다. 종료 시 자기 로그에 작업과 미커밋 상태를 append해줘. Codex가 결과를 검토한 뒤 다음 TASK 또는 기획 수정안을 작성한다.




제안 006은 하늘색 정착 경향까지 컨펌 완료다. 보라색을 cyan으로 교체한다. 하늘색 배회만 기존 배회 속도 ×0.7이며 사냥·도주·회피·관계 이동은 유지한다. 특수능력은 제안 007-r2로 컨펌 완료, 기획서 6절을 따른다.


제안 007-r2 승인: 발동형·행동강제형 판정을 분리하되 색별 E 시전·쿨다운은 공유한다. 파랑은 동족 포식, 초록은 버프·수확, 빨강은 집결 명령만 구현한다. 기본 돌진 거리 70%와 타격 폭 분리를 함께 검증한다.


성장 세계 인식은 승인된 v0.11 4절·제안 008을 따른다. 기존 줌 초기값을 유지하고 네 대표 배경 형상을 추가한다. 화면별 가독성·눈보라 가림·성장 보상을 검증하며, 배경은 충돌·피해·자원에 영향을 주지 않는다.

지역 조우는 승인된 v0.12 8절·제안 009-r1을 따른다. 고정 오브젝트 반복안을 대체하며 랜덤 위치에서 전조 후 먹이를 방출하고 오브젝트는 소멸한다. 직전 보상 원과 겹치는 위치는 제외한다.

Era 기본 순환은 v0.13 9절·제안 010 승인본을 따른다. 백로그 이벤트 연결 의견은 미승인 메모이며 구현 범위가 아니다. 전쟁 확장 제안 011은 승인됐으며 v0.14 9절을 따른다. 파멸 수정안 012-r1은 승인됐으며 v0.15 9절을 따른다.

숲 파멸은 포자를 미혹+산불로 대체한다. 플레이어 미혹 행동 강제는 후속 평가 대상이며 현재 입력·조작은 유지한다. 승인되지 않은 플레이어 자동 이동이나 입력 반전을 추가하지 않는다.

초원·사막 제안 013은 승인됐으며 v0.16 8절 확장 규칙을 따른다. 6종 단계에서 면적 10~25%·종류별 최소 3개 연결 지역으로 대체한다. 기존 4종 검증 이후 적용하며, 사막 유물은 일반 이동만 +10%/8초다. 두 지역의 파멸 사건은 별도 미정이다.

사용자 지시로 v0.17 10절은 최상위 설명 배너/아이콘을 줄이고 오오라·영역·능력 이펙트 중심으로 표현한다. 아트는 Codex 생성 컨셉 이미지로 스타일 승인받는다. 성장 피드백014 전체안은 미승인이다.

기본 아트는 사용자 정정으로 벡터 일러스트(concept-002-vector.png·벡터 프롬프트)다. 픽셀 선택 기록은 Codex 해석 오류로 대체했다. v0.19 10절을 따르며 스타일 때문에 판정·장애물 규칙을 바꾸지 않는다. 교체 구조·성장 피드백014 전체도 v0.20으로 승인됐다.

성장 피드백014·스타일교체22 구조는 사용자 컨펌 완료, v0.20 10절을 따른다. 구체 리소스/코드 경로는 조사 후 TASK로 정한다. 클라우드 작업 생성이나 GitHub 병합/배포 승인은 이번 기획 컨펌에 포함되지 않는다.

밸런싱 자동화015는 v0.21 11절로 승인됐다. TASK-001 최소 측정 조사와 연결하며 자동 탐색은 보고서/후보까지만, 기본 설정 적용은 별도 사용자 컨펌이다.

우선 보호 규칙: 기존 트위터 공개본/ball-game/을 새 기획으로 덮어쓰지 않는다. TASK-002에서 실제 배포 원본과 별도 새 저장소/URL 분리를 조사·준비한다. 현재 작업/미커밋을 보존하며 기존 master/Pages 경로로 새 게임을 push하지 않는다. 아트 제작 목록은 planning/25를 참고한다. Codex가 Claude에 메시지를 보내거나 source를 변경한 것은 아니다.

계열 빌드016은 v0.23 조건부 승인: 사용자 원래 방향이 아닌 Codex 실험안으로 후순위·기본 끔·단일 토글/독립 모듈·독립 커밋·취소 용이를 지킨다. 핵심 게임/피드백/아트/배포/기본 밸런싱 전에는 착수하지 않는다. 기능 끔에서 핵 생성·포인트·UI·AI목표·보정 모두 없어야 하며 기본 게임의 난수/저장/스탯을 바꾸지 않는다. 기본 켬은 별도 승인이다.
