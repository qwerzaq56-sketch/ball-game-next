## 보존 대상

사용자는 기존 게임 링크를 트위터에 배포했고 실제 플레이어가 사용 중이다. **https://qwerzaq56-sketch.github.io/ball-game/** 의 게임을 새 기획 구현으로 덮어쓰지 않는다. 다른 주소로 리다이렉트하거나 기존 플레이어의 로컬 기록을 지우지 않는다.

로컬 source HEAD 4e552a6이 실제 현재 공개 배포 커밋인지는 확인되지 않았다. Claude는 기존 Pages 배포 원본·설정·현재 배포 커밋과 파일을 확인하고 스냅샷/태그/자산을 보존한다. 단순 로컬 HEAD 태그만으로 공개 버전 보존 완료라고 보고하지 않는다.

## 권장 방식 — 별도 저장소·별도 Pages 주소

기존 저장소/Pages 설정을 유지하고 새 버전은 별도 저장소에서 구현·배포한다. 새 저장소 이름 후보는 ball-game-next이며 예상 주소는 https://qwerzaq56-sketch.github.io/ball-game-next/ 이다. 아직 생성/배포/주소 확보된 것은 아니다. 실제 저장소 이름·접근 권한은 확인 후 확정한다.

현재 Claude 작업의 미커밋 내용을 먼저 확인하고 보존한다. 기존 작업을 reset/clean하거나 두 에이전트가 동시에 checkout하지 않는다. 기존 배포를 건드리는 push 없이 새 저장소용 분리 작업영역을 마련하고, 진행 중 변경을 소유자 Claude가 안전하게 반영한다. 기획/handoff는 현재 공유 폴더에 유지한다.

개발 브랜치만 만들면 기존 master 병합으로 공개 사이트가 바뀔 수 있으므로 배포 대상 자체를 분리한다. 기존 저장소의 master/Pages 배포 경로에는 새 게임 변경을 보내지 않는다. 기존 사이트의 수정이 필요하면 별도 명시적 요청/승인으로 다룬다.

## 새 버전이 배포 가능한 조건

- 상대 자산 경로·모듈/config·새 주소에서 초기 로드/재시작이 동작한다.
- 기존 사이트와 같은 호스트라도 localStorage 키에 새 버전 접두어를 써 점수/설정/저장을 분리한다. 이전 데이터를 자동 삭제/변환하지 않는다.
- 캐시/서비스워커가 있다면 두 경로를 가로채지 않도록 범위와 자산 버전을 분리한다. 존재 여부부터 조사한다.
- 기존/신규 URL을 별도 브라우저에서 확인해 이전 게임 유지·새 게임 구분·독립 기록을 검증한다.
- 새 버전에는 최소 빌드 ID를 도움말/설정에 표시하고 배포 커밋/기획 버전/검증 보고서와 연결한다.
- 새 게임의 모든 미구현 기획을 완료로 표시하지 않는다. 첫 배포 기능과 알려진 한계를 릴리스 보고서에 명시한다.
