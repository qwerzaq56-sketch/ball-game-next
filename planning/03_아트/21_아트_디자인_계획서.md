# 아트·디자인 계획 초안

2026-10-02 / 상태: 계획 승인 완료·기본 벡터 스타일 확정 / 기준: 기획서 v0.15

사용자 백로그의 “아트 및 디자인 계획서도 하나 짜줘” 요청에 따른 문서다. 네온·모션그래픽·블룸·카메라의 원안은 사용자 직접 제안이며 아래 시각 문법과 제작 순서는 Codex 제안이다. 승인된 게임 규칙을 시각적으로 전달하는 목적이고 코드 구현·에셋 완성 문서는 아니다.

## 시각 방향

원형 개체와 어두운 지형 위에 절제된 발광을 사용한다. 평상시는 낮은 대비, 공격/위험 전조는 명확한 윤곽, 성장/직위 획득은 짧은 강조로 구분한다. 살아 있는 개체의 색은 종족 정보이므로 환경색이나 피격 표현으로 오래 덮지 않는다.

| 요소 | 표현 원칙 |
|---|---|
| 개체 | 실제 몸체 크기·종족 색 유지, 직위는 오오라·영역으로 표현, 별도 아이콘 최소화 |
| 공격/능력 | 실제 범위·방향·발동 시점이 읽히는 선/면 |
| 먹이 | 작은 광점, 개체와 구분되는 질감. 먹을 수 있는지 색으로만 판단시키지 않음 |
| 영역 | 얇은 경계와 낮은 대비 내부. 피해 구역처럼 보이지 않게 함 |
| 환경 위험 | 경계+패턴+동작 방향. 미혹은 상태 표식, 산불은 진행하는 불길 |
| 배경 | 개체보다 낮은 대비의 큰 윤곽·지역 질감. 실제 위험/충돌과 구분 |
| HUD | size·HP·스택·직위·능력 상태를 우선. 장식과 분리 |

## 바이옴 표현

바다는 어두운 청색 면과 해류 선, 설원은 낮은 대비 냉색 결/빙하 층, 숲은 짙은 녹색 결/뿌리, 화산은 어두운 지층/명확한 실제 마그마 경계를 사용한다. 지역색과 같은 종족도 윤곽으로 구분할 수 있어야 한다. 초원·사막은 승인된 제안 013의 풀/사구·피라미드 방향을 따른다. 구체 스타일 샘플은 이 아트 초안과 별도로 검토한다.

네 대표 배경은 승인된 세계 인식안대로 월드에 붙여 그린다. 미혹은 몸체 색을 바꾸기보다 윤곽의 미세한 흔들림과 상태 이펙트로 표현한다. 플레이어 입력을 왜곡하는 연출은 현재 승인 규칙에 포함하지 않는다.

## 제작 순서와 산출물

1. 개체·먹이·공격 전조·환경 경계·상태 아이콘의 작은 스타일 비교 화면을 만든다. 먼저 대표 밀집 전투에서 정보가 읽히는지 확인한다.
2. 성장 피드백 제안 014가 승인되면 기존 파티클·잔상·해금 배너를 재사용해 고리·성장 합산·직위 안내를 구현한다.
3. 네 바이옴의 배경 패턴과 큰 형상, 파멸의 전조/활성/종료를 같은 색·선 체계로 맞춘다. 기능별 승인 범위와 연결한다.
4. 기본/낮음/끔 장식 비교와 작은 화면 확인 후 필요한 추가 효과만 선택한다. 블룸은 현재 Canvas 구조에서 비용과 대안을 조사한 뒤 별도 구현안을 제출한다.

초기에는 Canvas 선·면·기존 입자를 우선 사용한다. 외부 이미지나 생성 에셋이 꼭 필요한 요소가 생기면 종류·해상도·수량·용도를 정해 별도 제작한다. 아직 존재하지 않는 이미지 에셋을 납품 완료로 표시하지 않는다.

## 평가와 남은 결정

위험/진영/크기가 읽히는지, 성장/타격/직위 획득의 강도가 구분되는지, 눈보라·밀집 효과·낮은 사양에서 가독성과 성능이 유지되는지 비교한다. 현재보다 장식이 많아도 판단이 어려워지면 실패다. 과한 섬광·지속 흔들림을 기본값으로 넣지 않는다.

정확한 색상값·폰트·아이콘 도형·블룸 구현·최종 에셋 스타일은 비교 화면 검토 전 미정이다. 문서 초안 승인과 구체 시각 샘플 승인은 구분한다. 성장 피드백 제안 014 수치는 별도 컨펌 대상이다.

## 실제 이미지로 컨펌하는 방식 — 사용자 지정

Codex가 컨셉 이미지를 직접 생성해 제시하고, 사용자는 그 이미지를 기준으로 스타일을 승인/수정한다. 텍스트 계획만으로 최종 아트를 승인한 것으로 처리하지 않는다. 첫 비교 이미지는 평상시 성장·최상위 오오라/능력·숲 미혹/산불의 세 장면이다. 종족색·몸체 크기·위험 전조를 유지하고 설명 배너·직위 아이콘은 최소화한다.

이미지의 스타일 승인과 게임 규칙·구현 자산 승인은 구분한다. 생성 이미지는 컨셉 참고이며 그대로 게임 배경이나 판정으로 적용하지 않는다. 이미지 생성 도구·최종 프롬프트·파일 경로를 art-concepts에 기록한다. 사용자 피드백을 받아 같은 컨셉의 수정 이미지를 만든다.

## 첫 컨셉 이미지

[컨셉 001](art-concepts/concept-001.png) / [최종 프롬프트](art-concepts/concept-001-prompt.md). 내장 image_gen으로 생성. 왼쪽 성장·가운데 최상위 오오라·오른쪽 미혹/산불. 스타일 컨펌 대기.

Codex 검토: 오오라와 종족색은 읽히고 설명 없이 위계가 보인다. 배경 뿌리와 불 표현은 실제 Canvas 구현에 맞춰 단순화할 필요가 있다. 생성 이미지의 비원형 영역 경계는 스타일 참고만 하고 실제 영역 판정은 승인된 원형 반경 600을 유지한다. 배경 뿌리는 장애물이 아니다. 이미지가 게임의 실제 화면·성능·판정을 보증하지 않는다.

## 스타일 후보 확장 — 사용자 요청

기존 컨셉001은 이미지·프롬프트를 그대로 보존한다. 전달받은 피드백인 벡터 일러스트·레트로 픽셀·팩맨 느낌을 비교 후보로 추가한다. 같은 성장/최상위/숲 파멸 장면을 각 스타일로 생성해 실제 이미지로 컨펌한다. 팩맨 느낌은 단순한 고전 아케이드 표현의 참고이며 캐릭터·미로를 복제하거나 벽 규칙을 추가하지 않는다.

장기적으로 [스타일 교체 시스템 초안](22_아트_스타일_교체_시스템.md)의 공통 의미 키·리소스팩·표현 설정으로 스타일을 분리한다. 개별 스타일 선택과 시스템 구조 승인은 구분한다.

## 선택된 기본 스타일 — 사용자 정정

2026-10-02, 사용자 “벡터 프롬프트” 정정에 따라 **벡터 일러스트**를 기본 스타일로 선택한다. 기준은 [컨셉002](art-concepts/concept-002-vector.png)와 [벡터 프롬프트](art-concepts/concept-002-vector-prompt.md)다. 앞선 “2번”을 비교 순서로 읽어 픽셀로 기록한 것은 Codex의 해석 오류였으며 대체됐다.

평면 색·명확한 기하 윤곽·단순 지형·절제된 오오라로 다듬는다. 컨셉 이미지는 래스터 참고이며 실제 SVG/Canvas 리소스가 완성된 것은 아니다. 배경 밀도와 대비를 낮추고 종족색·실제 크기·전조를 보존한다. 생성 이미지의 나무/바위는 장애물 규칙이 아니다. 기존001·벡터002·픽셀003·아케이드004와 모든 프롬프트는 그대로 보존한다.

스타일 방향은 확정됐고 성장 피드백014 규칙·교체 시스템 구조도 이후 v0.20으로 승인됐다. 기본 벡터 리소스팩부터 제작 범위를 정한다.

2026-10-02 사용자 “그 외 계획 다 승인”으로 제출된 이 계획도 승인했다. 계획 승인과 실제 리소스 생성/구현/배포 완료는 구분한다. 벡터 기본 스타일과 제작 순서·분리 배포 방식은 확정하며 차수별 실제 이미지와 구현 결과는 피드백을 계속 반영한다. 계열 빌드의 후순위·기본 끔·취소 용이 조건은 유지한다. 백로그에만 남은 미제안 아이디어는 이번 승인 범위가 아니다.
