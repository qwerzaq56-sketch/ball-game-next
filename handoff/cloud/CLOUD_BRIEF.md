## 1. 현재 상태
- 바닐라 JS ES module + Canvas, 서버 없이 정적 호스팅. 로컬 실행: `python -m http.server 8000` → http://localhost:8000 (file:// 더블클릭은 불가).
- 테스트 `node --test` **46/46 통과**. 측정 도구: `tools/behavior-metrics.mjs [seed] [seconds]`(아래 기준값), `tools/headless.mjs`(고정 1/60 실행기), `tools/review-scenarios.mjs`.
- 저장 키는 `ballgamenext_*`(기존 공개본 `ballgame_*`와 같은 도메인이라 반드시 분리). 기존 키를 읽거나 지우지 않는다.
- 이미 들어 있는 것: seed 난수, 공통 점수, 역할/성격/관계, 종족 5색 특성, 최상위 직위·영역(반경 600), 5색 최상위 능력(전조·쿨다운·명령), F2 AI Inspector(상태 창), F3 AI 머리 위 상태·성격 라벨, **일반 반격(v0.25)**.
- 기준 규칙(승인된 것만): 
  - 역할: size 순위 상위 20% 프레데터, 하위 40% 프레이, 나머지 포레이저(2초마다 평가, 같은 후보 2회 연속이면 전환). 성격 3종(성장 추구 34/리스크 회피 33/기회주의 33)은 성장해도 유지. 프레데터 관계 3종(종속 40/도전 30/독립 30).
  - 최상위 직위: **점수 상위 5위 중 size≥100**, 반경 600 영역. 일반 감지 320·동족 흡수 탐색 400·월드 5000×5000.
  - 위협 = 일반 감지 안의 자기 size 1.2배 이상 다른 색. 안전 = 위협과 중심거리 160 이상. 체력 30% 이하 회복, 60% 이상 복귀. 프레이 능동 사냥 금지, 일반 사냥은 상대 size 0.8배 이하만.
  - **일반 반격(v0.25, 사용자 지시)**: 다른 색에게 피해를 받으면 공격자를 3초 기억(환경 장판 틱 제외). 생존 규칙 뒤에서 공격 스택 있음·체력 30% 초과·공격자가 위협(1.2배 이상)이 아님·감지 320 이내면 반격. 리스크 회피형은 공격자 위치가 다른 위협으로부터 안전해야 함. 구현: `js/combat.js` `RETALIATION_MEMORY`, `js/ai.js` `decideAI`.
  - 능력(최상위, 쿨다운): 하늘색 냉기 휘두르기 10s, 파랑 파도(직사각형 길이 400·폭 180) 10s, 초록 사기 진작 12s, 빨강 전투 집결 12s, 노랑 모래바람 장판 14s. `js/abilities.js`.

## 2. 사용자 플레이 피드백 12건과 기준 측정치
측정 기준: `node tools/behavior-metrics.mjs 11 300` (seed 11, 300초, 플레이어 생존 고정·정지, AI 66~79마리).

| 지표 | 현재값(기준선) |
|---|---|
| AI 공격 시작 수 / 30초 구간 | 21, 25, 51, 41, 61, 72, 41, 60, 50, 78 (AI당 분당 1~3회) |
| AI 상태 변경 / 초 (20초 이상 생존 AI 164마리) | 중앙값 **1.01**, 상위 10% **1.80**, 최대 2.53 (초반 60초만 보면 훨씬 낮음 → 중반 이후가 문제) |
| search↔flee 전환 합계 (300초) | **10,226** (search>flee 5187 + flee>search 5039) |
| 최상위가 그 시점 최대 size가 아닌 비율 | 176 / 306 (58%) |

피드백(사용자 원문 요약)과 현재 사실:
1. 도주→탐색을 너무 반복함 / 상태 왔다갔다 — 위 전환 수. 도주 해제 경계·유지 시간이 없음(가설).
2. 중반쯤 다들 공격을 안 함. 가까이 붙으면 위협을 느껴 방어적으로 공격하거나 아예 도망가야 함 — 프레이 능동 공격 금지, 일반 사냥은 0.8배 이하만, 회피형은 대상 위치가 안전해야 함, 중반엔 크기가 비슷해 후보가 없음. 근접 방어 반응 규칙이 없음(일반 반격은 맞은 뒤에만).
3. 회피형이라도 어느 정도 적극적으로 공격하게 밸런싱하거나 비율을 줄일 것.
4. 탐색 거리가 너무 짧음 — 감지 320 vs 월드 5000.
5. 능력 사용이 가시적으로 표시되게 — 전조는 있으나 발동 순간·시전자 표시 약함.
6. 파랑 능력은 3방향 랜덤으로 — 현재 목표 방향 단일 직사각형.
7. 크기가 제일 큰 게 아닌데도 최상위가 유지됨 — 승인 규칙(점수 기준)대로 동작한 결과.
8. (이전) 맵이 너무 좁다(확장 또는 가장자리가 반대편과 이어지는 순환 맵), AI 이름(상위 20위), 점수 순위 HUD(상위 10위, 최상위 별도 표시), 맞아도 반격 안 함(→ 일반 반격으로 복원됨).

## 3. 이번 작업의 우선순위 (위에서 아래 순서)
1. **도주↔탐색 반복 완화**: 도주 해제 경계(예: 진입 160 / 해제 더 큰 값)나 최소 유지 시간으로 `search↔flee` 반복과 상태 변경 수를 줄인다. 규칙 변경이 작으므로 바로 구현 가능. **합격선(제안)**: 같은 측정에서 상태 변경 상위 10% 1.80 → 1.0 이하, search↔flee 합계 50% 이상 감소, AI 공격 시작 수는 악화 금지. 최상위 등장·점유량 감소 자체는 실패가 아님(2026-10-03 사용자 방향: 희소·빈번한 교체·장기 독점이 시기별로 다양하게 나타나는 생태계; GAME_DESIGN.md의 NEXT 절 참고). 다른 합격선을 제안하려면 근거 수치와 함께 보고서에 적는다.
2. **중반 소극성 해소**: 근접 시 방어 반응(공격 또는 도주) + 회피형 적극성/비율 조정. 성격 비율 34/33/33을 바꾸는 경우 **구현 전에 제안서(변경 전후 수치, 영향)를 먼저 제출**하고 사용자 컨펌 후 적용.
3. **탐색 거리**: 감지 거리 증가 vs 배회 목표 거리 증가 중 어느 쪽이 도주→탐색 반복·소극성 지표에 이로운지 측정으로 비교해 제안.
4. **능력 사용 가시성**: 발동 순간·피해 범위·시전자가 알아보이게. 최상위 직위 설명 배너/아이콘은 추가하지 않는다(사용자 방향: 최상위 설명 최소화).
5. **파랑 파도 3방향 랜덤**: 3방향 발사, 전조 3개 표시, 피해·쿨다운 정책은 제안으로 제출 후 적용.
6. 아래는 **사용자 결정/최소기획 필요 → 구현하지 말고 제안서만**: 최상위 직위 기준(크기 vs 점수), AI 이름(상위 20위)+순위 HUD(상위 10위, 최상위 별도 표시), 맵 크기 확장과 개체 수 스케일, 순환 맵.

## 4. 금지·주의
- 승인되지 않은 규칙(위 6번 항목, 성격 비율 변경 등)은 제안서로만 내고, 구현 변경은 사용자 컨펌 뒤에 한다. 제안은 "제안"이라고 표시한다.
- 디버그 기능(F1 패널, F2 인스펙터, F3 라벨)은 시뮬레이션 상태·난수를 바꾸지 않아야 한다.
- 난수는 기존 스트림(`random('ai')` 등)을 쓰고, 새 기능이 기존 스트림 소비 순서를 바꾸면 보고서에 명시한다.
- 브라우저 실제 입력·가독성 검증이 필요하면 가능한 범위를 시도하고, 못 하면 못 했다고 적는다.
- 보고서는 저장소 `reports/` 가 아니라 **작업 브랜치의 `CLOUD_REPORT.md`** 한 파일에 쓰고(변경 파일, 전후 측정치, 테스트 결과, 기획 차이·미해결 항목), 완료 후 브랜치명과 마지막 커밋을 알려라.
