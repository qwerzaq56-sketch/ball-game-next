# 클라우드 → 로컬 세션 인계

작성: 2026-10-05 한국 시간. 대상: `qwerzaq56-sketch/ball-game-next`의 로컬 컨셉 제작·사용자 컨펌 세션.

## 바로 이어받을 목표

사용자는 컨셉 제작·컨펌은 기존 로컬 원본을 직접 참조하는 로컬 세션에서, 게임 구현·테스트는 클라우드에서 이어가는 방식을 선택하고 작업 내용 전달을 요청했다. 지금 우선 작업은 **공 디자인 재시안 컨펌과 승인된 배경 방향의 후속 타일 시안**이다. 공 새 시안은 아직 승인받지 않았다. 사용자 답변을 임의 승인으로 처리하지 않는다.

작업 브랜치는 `codex/cloud-next-m4`. 인계 직전 최신 커밋은 `2d91d8a`(공 컨셉 자료), 게임 구현 최신 커밋은 `50c7c71`(M80), 구현 보고는 `b303ebe`. 이 문서가 추가된 이후 브랜치 최신 HEAD를 가져온다. 모든 변경은 원격 작업 브랜치에 푸시되어 있다. **main·통합 브랜치·ball-game 저장소는 변경하지 않는다.** 로컬의 미커밋 변경과 기존 원본을 보존한다.

로컬 변경/브랜치를 전환하지 않고 인계 문서만 확인하려면 저장소에서:

```sh
git fetch origin codex/cloud-next-m4
git show FETCH_HEAD:handoff/cloud/LOCAL_SESSION_HANDOFF.md
```

현재 로컬 작업 브랜치에 무조건 덮어쓰기·reset하지 않는다. 필요하면 별도 worktree에서 가져온 브랜치를 검토한다.

### M79 (`04a79c7`) — 흡수·동상·파랑·성장·최적화

- 흡수 취소 시 진행 감소에 맞춰 실제 낸 HP 환급. 사망·개체 제거·플레이어 새 생애에서도 이중/잘못된 환급 방지.
- 부상 대상은 흡수 시간·비용 감소. 큰 몸은 중심보다 표면 거리를 고려해 연결 유지. 기본 흡인력×1.2, 파랑 추가×1.3.
- 동상은 노출 게이지를 채워 발생하고 밖에서는 내려감. 서리 피난처는 즉시 해제하며 게이지 감소.
- 파랑 E: 일반 1개/최상위 3개 직선 파도, 가까울수록 피해 증가. R: 범위 내 모든 이동 엔티티 흡인, 가까울수록 강함. 이전 후보는 삭제하지 않고 보존.
- 초록 동행 빈도 완화(컨셉 유지). 실제 공격자에 반격 우선.
- 공통 성장 수신×0.5(먹이·사냥·흡수 한 번만 적용). 동일 먹이 경로의 목표 크기 도달 시간이 약 2배가 되는 방향. 기본 수치를 임의로 재조정하지 말고 사용자 체감과 실험 근거를 연결한다.
- 공격 판정 없는 상태의 공간 검색 생략·최대 몸 반경 공유·사망 능력 반복 해제 제거. 달리기/버프/동상/흡수 환급 및 일부 오브젝트 벡터 표현 추가.
- [기획](../../M79_GAMEPLAY_UPDATE_DESIGN.md), [상세 변경·측정](../../reports/M79-development.md).

### M80 (`50c7c71`) — 시뮬레이션 룸·의견 팝업

- 별도 작은 방, 계측 대상만 초기 소환. 시드·크기·종족·HP·거리·대상 수·고정/실제 AI·양쪽 최상위 설정.
- 실제 전투/흡수/스킬 엔진 공유. 환경·자연 소환·직위 재선출 제거. 스킬 자체의 소환은 실제 효과로 유지.
- 수치/스킬 후보를 바꾼 동일 조건 A/B 1~60초, HP·누적 피해·흡수 진행 그래프, 크기·잔존 대상 비교, 전체 조건/표본 JSON.
- 실험실 변경은 일반 플레이 기본값·저장값과 분리. 룸 내 스킬 저장 버튼 없음. 보기 확대는 물리 수치 비변경.
- 질문 큐 `data/designer-questions.json`을 AI가 작성·배포하면 게임/실험실에서 약 30초마다 확인해 팝업 표시. `window.__designerReview.ask(question)` 직접 호출 가능.

- **답변 서버 전송·AI 채팅 자동 전달은 없다.** 사용자에게 JSON을 전달받아야 한다. 채팅 질문이 모두 자동 팝업화되는 것도 아니다.

## 검증·작업 규칙

`codex/spec-sync` 병합 완료. **[handoff/cloud/CLOUD_RULES_P3.md](CLOUD_RULES_P3.md)** 및 [planning/rules/README.md](../../planning/rules/README.md)를 따른다. 마일스톤마다 관련 카드 확인 → 코드 주석/테스트 제목 ID 태그 → 도구 실행 → 상충 보고. 새로운 카드 상태는 제안, 승인 수치 변경은 전후/이유/근거와 미승인 변경 이력을 남긴다. 사용자 로컬 기획 정본과 클라우드 사본의 갱신을 구분한다.

```sh
node --test --test-isolation=none tests/*.test.mjs
node tools/spec-trace.mjs --impl . --commit <실제커밋SHA> --out /tmp/SPEC_TRACE.md
node tools/balance-sheet.mjs --impl . --commit <실제커밋SHA> --out /tmp/BALANCE_SHEET.md
```

최신 게임 변경 검증: **356개 테스트 통과**, PC/모바일 Chromium 오류0건. 이후 아트/문서만 변경했고 게임 테스트 재실행은 하지 않았다. 추적 카드107(승인99·제안8), 구현99/99·테스트제목 연결86/99·상충0·확인실패0·태그카드17. 수치217·규칙연결133·의도설명217. 추적의 검증은 테스트 제목 존재이며 테스트 실행 성공과 다른 지표다. 생성 추적 파일은 커밋하지 않는다.

로컬 Chromium 경로·Playwright 설치는 로컬 환경에서 확인한다. 클라우드의 `/usr/bin/chromium`, `/opt/codex/...` 경로를 그대로 쓰지 않는다. 클라우드에서 사용한 브라우저 검증 도구는 `tools/browser-simulation-room.mjs` 등이다.
