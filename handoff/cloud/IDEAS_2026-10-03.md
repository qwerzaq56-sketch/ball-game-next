# 사용자 아이디어 메모 (2026-10-03, 클라우드 전달용)

**상태: 사용자 직접 제안(미승인 규칙).** 구현하기 전에 아래 "확인할 점"을 반영한 **제안서**를 `CLOUD_REPORT.md`에 먼저 적고, 사용자 컨펌이 필요한 것은 컨펌 전 구현하지 않는다. 단, 아래 7번(HUD 접기)처럼 규칙이 아닌 표시 기능은 이미 구현 중인 순위 HUD에 맞춰 바로 구현해도 된다. 기존 승인 규칙과 충돌하는 지점은 숨기지 말고 보고서의 "충돌" 항목에 적는다.

## 사용자 원문
> 동행하는 경우 더 큰 적에게도 덤빌 확률이 생긴다.
>
> 아군에게 영향을 미치는 스킬은 전역적으로 ( 최상위 포식자 이펙트 전체 범위에 ) 작용하고, 영향을 받은 아군에게 이펙트를 줘서 표시한다.
>
> 초록색 능력은 나 + 아군에게 체력 재생 버프를 주는 걸로 한다.
>
> 프레데터의 스킬은 E 사용으로 쓰는 게 아닌 자동 발동으로 한다.
> 파란색의 파도 공격은 선딜 없애고 즉발로 한다.
>
> 탑텐 순위바는 접을 수 있게 이름 옆에 버튼 추가.
> 풀버전 -> 축약버전 -> 바 -> 풀버전 순으로 순환

## 항목별 현재 구현 사실과 확인할 점
1. **동행 중 더 큰 적에게도 덤빌 확률**
   - 현재: 위협(자기 size 1.2배 이상 다른 색)은 생존 규칙으로 무조건 도주한다(`js/ai.js decideAI`). 동행(`relationship` 상태, 종속형은 같은 색 최상위 주변 450~600 유지)은 도주·위험 판단과 무관하게 이동만 한다.
   - 확인할 점: "동행"의 범위(종속형만? 도전형 포함?), 확률 값과 판정 시점(판단 주기마다? 조우당 1회?), 덤비는 최대 상대 크기(1.5배? 제한 없음?), 최상위 본인이 가까이(영역 600 안) 있을 때만인지, 체력 조건, 실패 시 해제 조건. 생존 우선 규칙(HP 30% 이하 회복 등)은 유지하는 것을 기본으로 제안.
2. **아군 영향 스킬을 전역 적용 + 영향받은 아군에 이펙트 표시**
   - 현재: 초록 버프는 시전자 기준 반경 350 안 같은 색에만, 빨강 명령은 반경 450 안 같은 색 작은 AI에만 적용된다(`js/abilities.js`의 반경 표). 영향받은 아군 표시는 초록 호 하나뿐이다.
   - 확인할 점: "전역"의 범위 — ① 최상위 영역 반경 600 안인지 ② 이펙트(능력) 반경 전체인지 ③ 맵 전체인지. 사용자 표현은 "최상위 포식자 이펙트 전체 범위"이므로 ②를 기본안으로 하되 반경 값을 어떻게 정할지 제안. 같은 색 아군 전부인지, 대상 조건(역할·직위 없음 등)은 기존 명령 규칙을 유지하는지. 영향받은 아군에게는 색별 구분되는 이펙트(지속 시간 동안)를 표시. 감지되지 않은 아군까지 정보를 쓰는 문제는 보고.
3. **초록 능력 = 나 + 아군 체력 재생 버프**
   - 현재: 초록은 "사기 진작" — 반경 350 같은 색의 피해 +15%, 5초(`morale`, `damageMultiplier`). 동족 흡수 감소 특성은 별개이며 유지해야 함.
   - 확인할 점: 재생량(초당 최대 HP의 몇 %?)·지속 시간·중첩 정책(여러 초록 최상위), 기존 피해 +15%를 대체하는지 병행하는지(사용자 문장은 "재생 버프로 한다"이므로 대체가 기본안), 시전자 포함(나 + 아군), 기존 HP 회복 상태(체력 30% 이하 회복)와의 상호작용, 쿨다운 12초 유지 여부. 승인된 007-r2의 초록 정의가 바뀌므로 제안서 필수.
4. **프레데터 스킬은 E가 아닌 자동 발동**
   - 현재: AI 최상위는 이미 `considerAI`로 자동 시전하고, **플레이어가 최상위가 되면 E키로 수동 시전**한다. 입력 큐는 `js/main.js`(`_specialQueued`).
   - 확인할 점: "프레데터의 스킬"이 플레이어 최상위의 수동 시전을 없애고 AI와 같은 자동 발동으로 바꾸라는 뜻인지, 아니면 다른 의미인지. 플레이어 자동 발동 시 조건(적이 범위에 있을 때만), 발동 표시(전조/효과 가시성은 이미 별도 우선순위), 수동 조작을 완전히 제거할지 옵션으로 둘지 질문 형태로 보고서에 제안. 이전 승인안 "플레이어에게 자동 회피·반격 입력을 만들지 않는다"와의 관계를 정리.
5. **파랑 파도 선딜 제거(즉발)**
   - 현재: 파랑 파도 windup 0.6초 → 직사각형(길이 400·폭 180) 전조 후 판정(`js/abilities.js`). 피드백 중 "파랑 3방향 랜덤"(CLOUD_BRIEF 우선순위 5)과 같은 능력이다.
   - 확인할 점: 선딜 0이면 전조로 회피하는 승인된 능력 대응(회피 취소 등)이 사라진다. 즉발 파도의 회피 가능 여부(발사체가 날아가는 시간을 두는지, 완전 즉시 판정인지), 쿨다운·피해 조정 필요성, 3방향 랜덤과 합친 최종안을 하나로 제안. 다른 색 능력의 전조·선딜은 바꾸지 않는다.
6. (위 1~5 공통) 능력 사용 가시성 강화(CLOUD_BRIEF 우선순위 4)와 함께 설계해 이펙트가 중복·충돌하지 않게 한다.
7. **탑텐 순위바 접기 버튼 (바로 구현 가능, 표시 기능)**
   - 순위 HUD 제목(이름) 옆에 버튼을 두고 **풀버전 → 축약버전 → 바 → 풀버전** 순으로 순환한다. 풀버전은 현재의 전체 정보(이름·점수·최상위 표시 등), 축약버전은 한 줄 요약(순위·이름·점수 중 핵심), 바는 제목만 있는 한 줄 막대 같은 최소형으로 제안하고 보고서에 어떤 정보가 어느 단계에 보이는지 표로 적는다.
   - 선택한 단계는 `localStorage` 키 `ballgamenext_*` 접두어로 저장해도 된다(키 이름 충돌 주의, 기존 공개본 `ballgame_*` 키는 건드리지 않는다).
   - 클릭이 인스펙터·게임 입력과 겹치지 않아야 한다(이미 순위 HUD 클릭 처리 커밋이 있으니 그 구조를 재사용).
