# 밸런스 노트

`config/gameBalance.json` 기본값에 대한 실제 플레이 테스트(자동화된 브라우저 세션) 결과와 발견된
문제점을 정리한다.

## 발견된 문제와 조치

1. **초기 스폰 지점 주변에 적대 AI가 몰릴 수 있음.**
   플레이어는 항상 월드 정중앙(2500, 2500)에서 시작하는데, AI가 완전히 무작위 좌표에 스폰되다 보니
   운이 나쁘면 시작하자마자 여러 적대 AI에게 동시에 공격받아 체력이 급격히 깎이는 경우가 있었다
   (테스트 중 3초 만에 100 → 20까지 하락한 사례 확인).
   → **조치**: `Game.initWorld()`에서 AI 스폰 시 플레이어 시작 지점 반경 350px를 피하도록 재시도
   로직을 추가했다. 완전히 없애기보다는 "시작하자마자 사망"만 방지하는 최소한의 안전장치다.

2. **HUD 상태 텍스트와 색상 배지가 불일치할 수 있었음.**
   공격/회피 READY 텍스트 조건과 배지 색상(class) 조건이 서로 다른 상태값을 참조해, 쿨다운 중인데
   초록색으로 보이는 경우가 있었다. `js/ui.js`에서 동일한 `attackReady`/`dodgeReady` 불리언을
   텍스트와 클래스 양쪽에서 함께 사용하도록 수정했다.

## 확인된 정상 동작

- Growth → Size 변환 공식(`baseSize + sqrt(growth) * growthToSizeRatio`)이 의도대로 체감 성장
  곡선을 만든다: growth 82 → size 34.5, growth 413 → size 47대. 초반에는 크기가 빠르게 늘고
  후반으로 갈수록 완만해진다.
- `hpPerGrowth`로 인한 최대체력 스케일링이 공식대로 정확히 반영됨(`100 + growth*0.4`).
- 공격 텔레그래프(0.5초 대기 + 방향선/게이지) → 돌진(0.25초, 650px/s) → 회복(0.4초) 사이클이
  기대대로 작동하며, `attackDamage=20`으로 몇 번의 타격이면 초반 AI(HP ≈ 90~150)를 처치할 수 있다.
- 회피는 즉시 발동 + 짧은 무적 구간 + 3초 쿨다운으로, 공격과 뚜렷하게 다른 사용감을 준다.
- 적 사망 → 파편 5개 생성 → 같은 색 개체가 파편을 먹고 성장하는 파이프라인이 정상 동작.
- **AI 생태계가 플레이어 개입 없이도 스스로 굴러간다**: 테스트 중 플레이어를 조작하지 않는 동안에도
  자연적으로 AI 사망이 발생해 월드에 파편이 30개 이상 누적된 것을 확인했다. 이는 "AI끼리도 상호작용
  해야 한다"는 요구사항이 실제로 충족됨을 보여준다.
- 플레이어 사망 시 growth를 절반으로 줄이고 체력을 회복한 채 월드 중앙에서 재시작하는 리스폰 로직이
  정상 동작(과도한 페널티 없이 게임을 계속할 수 있음).

## 밸런스 관련 제안 (향후 조정 시 참고)

- `attack.attackCooldown`(1.5초)이 `attack.attackTelegraphTime + attackChargeDuration +
  attackRecoveryTime`(1.15초)보다 커서, 공격 한 사이클이 끝난 뒤에도 약 0.35초의 추가 대기가
  생긴다. 더 공격적인 템포를 원하면 쿨다운을 1.15~1.2 근처로 낮추는 것을 고려할 수 있다.
- 초반(성장 전) 플레이어는 공격이 잠겨 있어 적대 AI를 피하는 것 외에 대응 수단이 없다. 회피보다
  공격이 먼저 해금되므로, 공격 해금 전 구간(`growth < attackUnlockGrowth`)에서 이동속도 우위나
  약한 무적 프레임 같은 보완책을 주는 것도 고려해볼 만하다.
- AI의 `aggression`(0.55)과 `detectionRange`(320)는 기본값에서도 화면에 여러 개체가 동시에
  전투/추격 상태로 보일 만큼 활발했다 — 월드가 "살아있다"는 느낌을 주는 데 효과적이었다.
