# 밸런스 노트 — Version 0.2

Version 0.1의 노트는 [../v0.1/BALANCE_NOTES.md](../v0.1/BALANCE_NOTES.md)에 그대로 남아있다.
이 문서는 v0.2에서 새로 추가된 흡수/Skill Stage/사거리 스케일링 시스템에 대한 테스트 결과다.
(Browser pane이 숨겨진 상태에서는 `requestAnimationFrame`이 브라우저에 의해 사실상 멈추므로,
이번 테스트는 `game.update(dt)`를 고정 타임스텝으로 직접 호출하며 진행했다.)

## 설계 해석: "Orb 섭취"와 "같은 색상 흡수"를 분리한 이유

기획안 §5(색상 무관 Orb 섭취)와 §6-11(같은 색상 위계 + 흡수 저항)을 문자 그대로 하나의
공식으로 합치면, 방황하는 작은 Orb를 먹을 때도 흡수 저항 공식이 적용되어 초반 플레이가
느려지는 문제가 있었다(예: Size 17 AI가 Size 16 Orb를 먹으려 하면 sizeRatio 1.06 → 저항
시간 1초 이상). 이는 v0.1의 "스냅피한 성장 루프"를 해친다고 판단해, 다음과 같이 분리했다.

- **Orb(비전투 자원) 섭취**: 색상 무관, 즉시 — v0.1과 동일한 손맛 유지.
- **같은 색상 Player/AI 간 흡수**: §6에서 명시적으로 도입된 "위계" 개념을 그대로 적용,
  §7-11의 저항 시간이 여기에만 작동.

이 해석 덕분에 초반 성장 루프는 그대로 빠르고, "라이벌을 흡수한다"는 새로운 드라마는
의미 있는 크기 차이가 있을 때만 발생한다.

## 확인된 정상 동작 (수치 검증)

- **흡수 저항 공식**: Size 23.46 대상을 Size 41.29 흡수자가 공격 — sizeRatio 1.76 →
  계산된 저항 시간 1.821초. 손으로 계산한 값(`(1.0+23.46*0.1) * (1-0.76*0.6) = 1.821`)과
  정확히 일치.
- **즉시 흡수(sizeRatio ≥ 3.0)**: 별도 조건 분기가 0을 반환하는 것을 코드 리뷰 및 경계값
  테스트로 확인.
- **성장 전이**: 라이벌이 Growth 68을 보유한 상태로 흡수당했을 때, 흡수자의 Growth가 정확히
  +68 증가. Growth 0인 갓 스폰된 AI를 흡수했을 때는 정확히 +0 (의도된 동작 — "그 개체가
  쌓아온 성장치"를 그대로 넘겨받는 방식이므로 빈손으로 시작한 상대에게선 얻을 게 없다).
- **흡수 취소**: 흡수 진행 중인 대상에게 강제로 큰 Growth를 주입해 크기를 역전시키자,
  다음 프레임에 즉시 취소되고 대상이 생존하는 것을 확인.
- **플레이어도 동일 규칙 적용**: 플레이어보다 훨씬 큰 같은 색 AI를 붙여 놓자 플레이어가
  흡수되어 "ABSORBED — RESPAWNING..." 배너와 함께 리스폰(Growth 절반 리셋, HP 전체 회복)
  — Player/AI 규칙이 실제로 완전히 통일되어 있음을 확인.
- **Skill Stage 경계값**: Size 39 → Stage 0(공격 LOCKED), Size 40 → Stage 1(공격 READY),
  Size 79 → Stage 1, Size 80 → Stage 2(회피 READY)까지 정확히 임계값에서 전환.
- **사거리 스케일링**: `attackRange = 80 + (size-40)*1.0`, `dodgeDistance = 100 +
  (size-40)*1.0` 공식이 Size 20/40/80/150 전 구간에서 정확히 일치.
- **공격 준비 시간**: `attack.attackTelegraphTime` 값이 0.2로 로드되는 것 확인. 텔레그래프
  방향선 길이도 새 `currentAttackRange` 스냅샷 기준으로 늘어나 시각적으로도 "사거리가 커졌다"는
  피드백이 자연스럽게 따라온다.
- **갓 스폰된 AI는 공격 불가**: 초기 AI 크기(약 17~28)가 `attackUnlockSize`(40)보다 한참
  작아 Stage 0으로 시작 — `decideAI()`가 이 상태에서 적대 개체를 만나도 전투를 선택하지 않고
  무시/도주만 하는 것을 확인. 결과적으로 "어린 개체는 서로 잡아먹기 경쟁만 하다가, 다 크고
  나서야 전투에 뛰어든다"는 자연스러운 성장 곡선이 만들어졌다.

## 밸런스 관련 제안

- `skills.attackUnlockSize`(40)가 AI의 평균 초기 크기(~17~28)보다 상당히 높아서, 초반 AI
  개체군은 상당 시간 동안 전투 없이 Orb/약자 흡수 경쟁만 벌인다. 이는 "성장하지 않으면
  싸울 수 없다"는 v0.2의 메시지에는 부합하지만, 맵이 전투로 붐비는 시점이 v0.1보다 늦어진다.
  더 빠른 템포를 원하면 `attackUnlockSize`를 25~30 정도로 낮추는 것을 고려할 수 있다.
- 흡수 저항 시간(`baseResistanceTime=1.0` + 크기 비례)이 대형 개체끼리는 꽤 길어질 수
  있다(예: Size 100 대상은 기본만 11초). 저항 시간 상한(`maxResistanceTime` 같은 캡)을
  추가로 노출하는 것도 고려할 만하다 — 현재는 `sizeRatioForInstantAbsorption`으로만
  상한을 우회할 수 있다.
- 흡수 중 대상이 완전히 무력화되므로, 다대일 상황에서 "붙잡힌 대상을 다른 세력이 손쉽게
  공격"하는 조합이 매우 강력해질 수 있다. 프로토타입 단계에서는 의도된 리스크/보상으로
  판단했지만, 실제 플레이에서 과하게 느껴지면 흡수 중 일시 무적/피해 감소를 추가하는 방안도
  있다.
