# 밸런스 노트 — Version 0.3

Version 0.1/0.2 노트는 각 버전 폴더에 그대로 남아있다
([../v0.1/BALANCE_NOTES.md](../v0.1/BALANCE_NOTES.md),
[../v0.2/BALANCE_NOTES.md](../v0.2/BALANCE_NOTES.md)). 이 문서는 v0.3 QA 기획안(§1-16)에서
요청한 항목들을 실제로 구현 후 `game.update(dt)`를 고정 타임스텝으로 직접 호출하며 테스트한
결과다. (v0.2 노트에서 설명했듯, Browser pane이 숨겨지면 `requestAnimationFrame`이 브라우저에
의해 사실상 멈추기 때문에 실시간 대기 대신 고정 스텝 시뮬레이션으로 검증했다.)

## 가장 중요한 발견: 기획안 예시값으로는 흡수가 사실상 불가능했다

기획안 §1-3의 예시값(`pullForce: 0.25`, `escapeDistance: 50`, `breakDistance: 70`)을 그대로
구현한 뒤, "흡수자가 적극적으로 추격해도 흡수가 실제로 완료되는가"를 테스트했다.

결과: **10초간 쉬지 않고 추격해도 단 한 번도 완료되지 않았다.** 원인을 프레임 단위로
추적한 결과:

1. 대상이 흡수당하는 즉시 흡수자로부터 정반대 방향으로 도주를 시작한다(§1-2 요구사항대로
   정상 동작).
2. 초반 한두 프레임 동안 "흡수자가 대상의 이전 위치를 향해 움직이는" 순수 추격(pure
   pursuit) 특성상 방향 전환에 약간의 지연이 생기고, 그 사이 대상은 이미 상당한 거리를
   벌린다.
3. `breakDistance`가 70으로 너무 타이트해서, 이 초반 지연만으로도 즉시 취소 조건을
   만족해버린다. 흡수자의 속도 우위(Player 250 vs AI ~130)가 실제로 거리를 좁히기
   시작하기도 전에 이미 취소되는 것이다.

즉, 기획안 예시값은 **"탈출 가능해야 한다"는 요구사항은 과도하게 충족하지만, "크기 차이가
크면 흡수가 쉬워야 한다"는 기존 요구사항(v0.2부터 유지)을 사실상 무력화**시켰다. 흡수
시스템 자체가 사실상 사용 불가능한 장식으로 전락하는 것을 확인했다.

### 조치

- `pullForce`: 0.25 → **0.35** (초당 흡수자 쪽으로 좁혀지는 비율)
- `breakDistance`: 70 → **110** (초반 추격 지연으로 인한 오탈출을 방지할 여유 확보)
- `escapeDistance`(진행도가 실제로 쌓이는 거리, 50)는 그대로 유지

조정 후 재테스트: 크기비 1.6 정도의 상대를 적극적으로 추격하면 약 3초 내에 흡수가
완료되고, 반대로 플레이어가 그 자리에 가만히 있지 않고 이동만 해도(추격 없이 그냥
멀어지기만 해도) 1.5초 이내에 확실히 탈출된다. 두 요구사항이 양립함을 확인했다.

또한 AI가 "흡수 중 도주" 상태일 때는 일반 저체력 도주(flee)에 붙는 1.3배 속도 보너스를
주지 않도록 별도 처리했다(`js/ai.js#moveAI`) — 붙잡힌 상태에서 오히려 더 빨라지는 것은
어색하고, 이 보너스가 있으면 위 문제가 더 심해진다.

## §1 흡수 조작감 — 체크리스트 결과

- [x] 흡수 중 이동하여 탈출 가능 — player가 흡수 시작 직후 반대 방향으로 1.5초간 이동하는
  것만으로 거리가 `breakDistance`를 넘어 확실히 취소됨을 확인.
- [x] 흡수력이 이전보다 약해짐 — 이전(v0.2)의 흡수는 프레임마다 고정 비율(0.06~0.26)을
  직접 위치에 적용해 프레임레이트에 관계없이 사실상 즉시 붙잡히는 구조였다(초당 몇 번이고
  누적 적용되어 사실상 탈출 불가능했던 것이 이번 QA의 원인). v0.3은
  `1-(1-pullForce)^dt` 형태의 지수 감쇠로 교체해 프레임레이트 독립적이면서 확실히 약하다.
- [x] 크기 차이가 클수록 흡수가 빠름 — 기존 저항시간 공식(sizeRatio 기반)은 그대로 유지.
- [x] 공격받으면 흡수 취소 — 제3자가 흡수 중인 대상을 공격하면 즉시 취소되고 넉백도 함께
  적용됨을 확인(`combat.js#applyDamage`).

## §2-3 스폰 밀도 / 적 크기 분포

- Orb: 초기 260→**400**, 최대 320→**500**, 재생성 간격 0.8→**0.4초**.
- Enemy: 기존에는 게임 시작 시 40마리를 스폰한 뒤 죽으면 그만이었다(재생성 없음). v0.3은
  `enemySpawnInterval`(2초)마다 개체 수가 `maxEnemyCount`(80) 미만이면 새로 스폰한다.
  절반을 강제로 제거한 뒤 10초 시뮬레이션한 결과 40→45마리로 정상 보충되는 것을 확인(2초당
  1마리, 계산과 일치).
- 크기 분포: `spawnAI()`를 2000회 호출해 통계를 낸 결과 소형 59.6% / 중형 31.6% / 대형
  8.9% — 설정한 60/30/10%와 거의 정확히 일치.

## §4 사운드

실제 오디오 파일(.wav/.ogg 등)을 배포하는 대신 **Web Audio API로 즉석 합성**하는 방식을
선택했다(`js/audio.js`). 이유:

1. 바이너리 에셋이 없으므로 §5(다른 PC 배포)의 "리소스 누락" 리스크가 원천적으로 사라진다.
2. 라이선스가 불분명한 무료 SFX를 구해 쓰는 것보다 안전하다.
3. `gameBalance.json`의 `audio.*` 볼륨 값으로 여전히 완전히 제어 가능하다.

요청된 8개 이벤트(성장/공격 준비/돌진/명중/피격/회피/사망/해금)에 모두 대응하는 메서드를
구현했고, 콘솔에서 전부 예외 없이 실행되는 것을 확인했다(브라우저 자동화 환경이라 실제
청취 확인은 불가능했으나, AudioContext 생성과 노드 그래프 구성에는 오류가 없다). 노이즈/톤은
전부 사용자 제스처 이후(마우스 클릭 또는 키 입력) 최초 호출되므로 자동재생 정책에도 걸리지
않는다.

무분별한 소음을 피하기 위해, 맵 전역이 아니라 **플레이어 본인과 직접 관련된 이벤트에만**
소리를 낸다(예: 플레이어의 공격이 명중했을 때만 hit 사운드, 플레이어가 직접 맞았을 때만
damage 사운드). AI끼리의 전투에는 소리를 내지 않는다 — 그렇지 않으면 맵에 수십 마리가
동시에 싸우는 v0.3에서 사운드가 끊임없이 겹쳐 소음이 될 것으로 판단했다.

## §9-13 피격 피드백 / 넉백

- Hit Flash: `combat.hitFlashDuration`(0.08초)로 분리, 기존 하드코딩된 0.15초보다 짧고
  더 "탁" 하는 느낌.
- Hit Particle: 개수 8→12, 속도 범위 상향, `combat.hitParticleLifetime`(0.25초)로 분리.
- 넉백: `applyDamage`에 attacker 인자를 추가해 방향을 계산하고,
  `speed = knockbackForce * knockbackResistance / (targetSize / referenceSize)` 공식으로
  큰 대상일수록 덜 밀리게 구현. 직접 테스트로 왼쪽에서 맞은 대상이 오른쪽으로 정확히
  밀려나는 것, 시간이 지나며 감쇠하는 것을 확인.
- 흡수 중 피격 시 취소: §1 체크리스트 참고.

## §6 Kill Count

- 플레이어의 공격이 최종 타격인 처치만 카운트됨을 확인(`applyDamage` → `onEntityDeath(target,
  attacker)` → `attacker === player`일 때만 `+1`).
- 흡수로 인한 제거는 의도적으로 카운트에서 제외(`absorption.js`, 기획안 §6-2 "직접
  공격하여 HP를 0으로 만든 경우"에 흡수는 해당하지 않는다고 해석) — 직접 테스트로 흡수
  완료 후에도 Kill Count가 그대로임을 확인.
- AI끼리의 전투는 애초에 `attacker`가 player가 아니므로 카운트되지 않는다.

## §7-8 회피 이펙트 / 입력

- 회피 잔상을 인덱스 기반 페이드(최대 6개 유지)에서 **수명 기반**(`dodge.effectLifetime`,
  0.3초)으로 교체. 이전 방식은 배열 길이만 제한할 뿐 회피가 끝나도 잔상을 지우는 코드가
  전혀 없어 마지막 잔상들이 그 자리에 영원히 남아있던 실제 버그였다. 회피 종료 후
  0.3초 뒤 잔상 배열이 정확히 0개가 되는 것을 확인.
- 회피가 공격의 TELEGRAPH/CHARGING/RECOVERY 어느 단계에 있든 즉시 취소하고 발동되는 것을
  확인(`combat.js#startDodge`가 공격 상태를 강제로 READY로 되돌림).

## 추가로 조정이 필요할 수 있는 수치

- `spawning.maxEnemyCount`(80)와 `spawning.enemySpawnInterval`(2초) 조합은 완전히
  전멸한 상태에서 최대치까지 회복하는 데 약 160초가 걸린다. 초반 밀도는 크게 개선됐지만,
  대규모 전투 이후 회복 속도가 느리게 느껴지면 간격을 1.0~1.5초로 낮추는 것을 고려할 수
  있다.
- `absorption.breakDistance`(110)는 이번 조정으로 "추격하면 잡힌다"를 살렸지만, 맵이
  좁게 느껴질 정도로 물리적으로 밀집한 전투(다수 개체가 한 지점에 몰림)에서는 여전히
  자주 취소될 수 있다. 실제 장시간 플레이에서 "흡수가 너무 자주 실패한다"는 피드백이
  나오면 120~140까지 추가로 올리는 것을 권장한다.
- 사운드는 현재 정적인 톤 합성이라 반복 청취 시 단조로울 수 있다. 추후 약간의 피치
  랜덤화(±10% 정도)를 추가하면 반복 피로를 줄일 수 있을 것으로 보인다.
